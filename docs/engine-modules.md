# Engine modules

## core

Generic ECS, header only, raylib-free. `entity.hpp`: `EntityId` and `Entity { id, label }`. `registry.hpp`: `Registry` creates/destroys entities (ids sequential, never reused), attaches components (`add<C>`, `get<C>`, `has<C>`, `remove<C>`) and runs systems over them with `each<Cs...>(fn)` (creation order; walks a snapshot of the smallest requested pool, so `fn` may add or remove components). Lookups are O(1): ids index vectors, each pool keeps its owners sorted by id; a component's address is stable until it is removed or replaced. `on_add<C>(hook)` / `on_remove<C>(hook)` run after an add (a replacement too) and before a removal, replacement or `destroy` (not when the registry itself dies). `context<T>()` stores one object of type T with the registry (created on first use; `find_context<T>()` is the const lookup), used for indexes such as `world::Occupancy`. Not copyable.

## event

Header only. `EventBus` (synchronous, type-safe publish/subscribe), `ScopedSubscription` (RAII unsubscribe) and `subscribe_scoped<E>()`.

## ui

Reusable, raylib-free widget toolkit: `Style` (CSS-like), builders (HTML-like), `Widget` base, `Label`, `Button`, `Input`, `Checkbox`, `Dropdown` (its open list is a `column()` of option `Button`s below the header, each as big as it, drawn as the overlay; the hovered option, or the selected one, shows focused), `Card` (an alias of `Box`: `ui::card()` is a column with `theme::card_style()`, bevel included, and stretched children), `Box` (flexbox-like container built with `ui::row()` / `ui::column()` and Tailwind-like chained calls: `.padding()`, `.gap()`, `.align(Align::Start|Center|End|Stretch)`, `.justify(Justify::Start|Center|End|SpaceBetween)`, `.width()`, `.height()`, `.min_width()` / `.max_width()` / `.min_height()` / `.max_height()` (also `Style` fields, clamping the resolved size), `.background()`, `.border()`; a child's `Flex{grow, shrink}` (second argument of `.child()` / `.child_ref()`, default 0 / 0) shares the free main-axis space by grow factor, or gives up the overflow by shrink factor down to its min size; a child's own fixed cross size wins over `Align::Stretch`, and a box with a fixed width/height keeps it whatever room it is offered; `.child()` owns a widget, `.child_ref()` places one the caller owns (it must outlive the box); `.style()` replaces the whole style, so call it first; `build()` is single use; a child hidden with `Widget::set_visible(false)` takes no room or gap, is not drawn, ignores the pointer and gets empty bounds, so a panel can keep one tree and toggle parts of it; containers measure children with `Widget::measure()`, which caches `preferred_size()` for one `LayoutPass` (opened by the outermost `layout()`, so each widget is measured once per layout and again on the next one); `preferred_size()` and `layout()` measure the children with the same rules, so screens describe structure instead of computing positions; `ui::centered(size, area)` centres a rect), `Grid` (`ui::grid(columns).gap(g).child(...)`: children fill rows left to right and wrap after `columns`, every cell as big as the biggest child; hidden children are skipped), `TabBar` (a `Composite`: a `row()` of `Button`s, one active, restyled with `Widget::set_style()` when the active tab changes; `theme::tab_style()` / `active_tab_style()` (green) / `disabled_tab_style()`; disabled tabs ignore clicks; `on_change(index)`), `ScrollBox` (`ui::scroll_box(child).step(px).max_height(h)`: a vertical view over a taller child, laid out at full height and moved by `offset()`; drawing is clipped to the view and the pointer only reaches the child inside it; as high as `max_height` or the room its parent gives it (`Flex`); a scrollbar while it overflows; `scroll(notches)` moves `step` pixels per notch), `Widget::handle_scroll(point, notches)` (the wheel: returns true once a widget took it; `Box` passes it to its children, a `ScrollBox` under the pointer takes it), `Composite` (`composite.hpp`: a widget made of a Box tree it keeps between frames; it calls the subclass's `sync(canvas)` at most once per `LayoutPass`, where the subclass builds the tree with `set_tree()` the first time or when its shape changes and otherwise updates texts, colours and states in place, so controls keep their hover and focus; measuring, layout, drawing, pointer and wheel go to the tree), small setters for that in-place update (`Label::set_text/set_color`, `Button::set_text`, `Checkbox::set_checked` (no notification), `Widget::set_width`, `Widget::set_style`, `Widget::set_visible`), `draw_raised()` (paints any area like a button face: fill, outline, bevel), `FocusGroup`/`Focusable` (keyboard navigation), `Canvas` (drawing surface; `push_clip(rect)` / `pop_clip()` nest and intersect, the backend implements `apply_clip()`). Only `raylib_canvas.cpp` touches raylib (`RaylibCanvas::screen_size()` gives the window size to the views).

## input

- `Key`, `Action`, `Keyboard` (interface), `InputMap` (key → action bindings, rebindable) and `InputHandler` (polls the keyboard, runs the handler of each triggered action; `is_held(Action)` for continuous input such as walking).
- `Keyboard::next_char()` returns the characters typed this frame; `Keyboard::is_down()` is true while a key is held.
- Bindings: `menu_defaults()`; `text_entry_defaults()` (leaves letters and Space unbound); `world_defaults()`: WASD → `MoveUp/MoveDown/MoveLeft/MoveRight`, arrows/Enter/Space navigate/confirm, Esc → `Pause`, Tab → `ToggleInventory`, B → `ToggleBuildMenu`, F → `ToggleVehicle`.
- `Pointer` (`pointer.hpp`), the mouse counterpart: `position()`, `released()` (left click), `down()` (left button held), `secondary_down()` / `secondary_released()` (right button), `scroll()` (wheel). `PointerGate` (`pointer_gate.hpp`) wraps a pointer for stacked layers: after `claim()` it reports no click, held button (either) or wheel (position only) until `reset()`. The world screen injects it into its renderers; the menu screens inject it into their `scene::PanelController`.
- Only `raylib_keyboard.cpp` and `raylib_pointer.cpp` touch raylib.

## graphics

- `graphics/` holds everything about pictures: textures, sprites, animations and which sprite the game shows for what. Unlike `ui/` it may depend on other layers (e.g. `world::TileType`); only `raylib_texture_loader.cpp` touches raylib.
- `TextureManager`, a singleton (`TextureManager::instance()`): `Game::start_up()` installs the loader (`set_loader()`). `register_texture(name, path)` returns a `TextureId` (an index; registering a name again keeps its id and swaps the file). `find(id)` / `find(name)` load on first use and give null when the file cannot be read (not retried); `get(name)` returns the **fallback texture** instead (a generated magenta/black checkerboard, created once through `TextureLoader::create_placeholder()`, null only when there is no loader); `fallback()` gives it directly. Draw loops use ids, never names.
- Drawing: `ui::Canvas::draw_texture(texture, dest, TextureDraw{source, tint, flip_x, flip_y, rotation})` (the 2-argument overload draws the whole texture).
- **Sprites are data, not code.** Each sheet has a `.sprite` file next to its PNG under `<data dir>/sprite/`, written by the generators in `tools/sprites/` (`pixel.write_sprite`). `sprite_definition.hpp`: `parse_sprite_definition(text, &error)` reads its `key=value` lines (`#` comments): `texture`, `frame_width`, `frame_height` (required), `columns`, `rows` (default 1), `anchor_x`, `anchor_y` (the pixel on the ground point, default 0) and `clip.<name>=first,count,fps,loop|once` (a run of columns along a row). Unknown keys, bad numbers and clips outside their row are rejected.
- `sprite_library.hpp`: `load_sprite_library(textures, root)` reads every `**/*.sprite` under `root` (sorted, so ids are stable) into a `SpriteLibrary`, naming each by its path without extension (`buildings/headquarters`) and registering its sheet with the `TextureManager`; a broken file is logged and skipped, a missing folder gives an empty library. `find(name)` → `SpriteId`; `clip(sprite, name)` → `ClipHandle` (falls back to `idle`, then to column 0 held); `frame(clip, row, seconds)` → `SpriteFrame{texture, source, size, anchor}` (looping clips start over, `once` clips hold their last frame; `row` wraps into the sheet). `SpriteFrame::dest(ground, scale)` places it so the anchor lands on `ground` at `scale` times the default zoom.
- `game_sprites.hpp`: `GameSprites` (owned by `Game`, `game.sprites()`) picks sprites **by naming convention**, resolved once in its constructor so lookups only index arrays: `building(type, seconds)` → `buildings/<building key in snake_case>` (`ElectronicFactory` → `buildings/electronic_factory`), clip `idle`; `tile(type, tile, seconds)` → `environment/<tile type>`, clip `idle`, each sheet row a variant picked per tile from a hash of its coordinates (grass has 4); `character(facing, state, seconds)` → `units/character`, row = `world::Direction` (enum order), clip `idle` / `walk` / `run` (run falls back to walk); `battle_tank(facing, state, seconds)` → `units/battle_tank` (generated by `tools/sprites/vehicles.py`), row = `world::Direction`, clip `idle` when parked and `drive` while moving (falls back to idle). None means the plain shape stays. **A new sprite needs no C++**: generate the PNG + `.sprite` with the right name. `GameSprites::none()` is an empty instance for views built without sprites.
- `sprite.hpp`: `draw_frame(canvas, frame, dest)` draws a `SpriteFrame` when its texture loads (false otherwise, so what is under it stays). `Sprite` (texture name + optional region) with `draw_sprite()` (fallback when missing) / `draw_loaded_sprite()` remain for UI icons drawn by name.
- `icons.hpp`: **UI icons** are plain PNGs under `<data dir>/icon/` (generated by `tools/sprites/icons.py`); `register_icons(textures, folder)` (called by `Game` at start up) registers each as a texture named by its file stem. Names: `icon_<building key in snake_case>` and `icon_tab_<category>` (construction menu), `item_<item>` (`item_icon_name(type)`, inventory slots; the item colour shows without one), `menu_<button>` (title menu, via `ui::Button::set_icon`). A missing icon keeps the old look.
- `TextureLoader` is the interface; only `raylib_texture_loader.cpp` touches raylib. Tests install a fake loader and call `reset()` in set-up/tear-down.

## logging

`logging::info()` / `logging::warning()` write to stderr (`[INFO]` / `[WARN]`); `set_sink()` redirects messages (tests capture them). Raylib-free.

## text

Header only, raylib-free, usable from any module (including `world::`). `parse.hpp`: `text::parse<T>(text)` reads the whole text as an integer or floating-point `T` (empty on anything else, a '+', spaces, or overflow; unsigned rejects '-'; locale-independent), and `text::format(value)` writes the shortest text that `parse<T>()` reads back exactly. Use them for every number read from or written to a file instead of hand-written loops or `std::sto*`.
