# World scene (`scene/world/`)

## `WorldModel`

- `WorldModel(bus, input, save)` owns the `core::Registry`, the `Camera` (`camera()`), the `Terrain` built from `save.seed` (`terrain()`), and its `world::System`s in a `std::vector<std::unique_ptr<::world::System>>`, run in order in `update()`.
- It passes the `input::InputHandler` to `world::PlayerInputSystem`, so movement never goes through the controller. `make_world_scene(game, save)` creates the handler and shares it with the controller, which only handles the pause/menu actions and zooms the camera with the mouse wheel (`Camera::MinZoom`/`MaxZoom`).
- Restores the entities in its constructor (spawning the default player through the `EntityFactory` when the save has none or no player) and centres the camera on the player.
- `save_game()` returns the header plus a fresh snapshot; `save_header()` is the header alone. Not copyable or movable (the serializer and systems refer to its members).
- **Pause**: `toggle_pause()`; no simulation while paused. `cancel()` (Esc) closes the player menu first, otherwise toggles the pause.
- **Player menu**: `toggle_player_menu()` (ignored while paused), `close_player_menu()`, `is_player_menu_open()`; the simulation keeps running while it is open.
- **Build bar**: `toggle_build_bar()` (ignored while paused), `build_status()`, `placement_status()` (every rule incl. tile and cost), `request_build(type, tile)` (publishes `BuildRequested`).
- **Work and transfer**: `work_on(tile | nullopt)`; `open_transfer(tile)` (a finished building with an inventory within `TransferReach`), `transfer_target()`, `close_transfer()` (also closed by `update()` when out of reach and by `cancel()` first), `request_transfer()`.

## `WorldView` and renderers

`WorldView` hosts a list of `scene::world::Renderer`s (`renderer.hpp`: `visible()`, `update()` polls input, `draw(canvas, screen)`, `captures_pointer(point)`), built by `make_world_scene` and injected. Drawn in list order (first = bottom), updated topmost first, skipped while not `visible()`. The renderers read the mouse through a shared `input::PointerGate` owned with the view: each frame the view resets it, and after updating a renderer whose `captures_pointer()` was true (from the last layout) it claims the gate, so the renderers below see no click, held button or wheel. `BuildingPanel`, `PlayerMenu` and `WorldMenu` are modal (capture everywhere while visible); `PlayerHud` captures only over its bar and open list. `BuildingPanel` keeps one widget tree per building and updates its texts and visibility in place each frame. A renderer gets its dependencies (registry, bus, input) in its constructor, like a model system. Renderers live in `render/`; in draw order:

- `TerrainRenderer(terrain, camera, clock)`: the visible tiles as isometric diamonds in `tile_color(TileType)`, with `graphics::tile_sprite(type, tile, seconds)` drawn over each diamond's bounding box by `graphics::draw_loaded_sprite()` (a missing file just leaves the colour; see engine-modules.md#graphics). `clock` gives the animation seconds (since the world scene started; none = first frame).
- `EntityRenderer(registry, camera, clock)`: each entity with a `Position` as a `Cube`, with its label and, for characters, the state. Buildings are boxes covering their whole footprint (`Cube::footprint()`, `BuildingCubeSize` per tile), blue, grey with a progress % while a construction site. Workers show their `::world::worker_type()` instead ("Worker (Miner)", "Worker (Idle)"), and a worker at work (`::world::is_at_work()`) is not drawn. Drawn in `::world::painter_order()` of their footprints, so a character in front of or behind a big building overlaps it correctly. A character is drawn as `graphics::character_sprite(facing, state)` (its `Facing` row, standing or walk frames). A finished building with a `graphics::building_sprite()` (only the headquarters so far) is drawn as that sprite instead of its box, its anchor on the footprint centre and scaled with the zoom, animated by `clock` (shared with the terrain); the label sits above the sprite. A construction site, or a sprite whose file does not load, stays a box.
- `SiteWork(model, pointer)`: draws nothing; calls `work_on(tile)` each frame while the left button is held over the world, `work_on(nullopt)` otherwise (pausing and the player menu also stop work); a click calls `open_transfer(tile)`. Hidden while a transfer is open.
- `UnitCommand(model, pointer)` (above `SiteWork`): left button held and dragged past `SelectionDragThreshold` (6 px) draws a box and selects on release (`select_units()`), capturing the pointer while dragging so `SiteWork` neither works nor opens a transfer; pressing the left button calls `shoot_at(tile)` (the player shoots: `shootable_at()` + `ShotRequested`, next tick) and each further held frame (while not dragging) `hold_trigger(tile)`, which fires again only with a `FireMode::Automatic` weapon; a plain left click calls `clear_selection()` (`SiteWork` still gets the click); a right click calls `order_units(tile)`: on a `Supply` building (the barracks) the selection gets `UnitsResupplyRequested`; when `shootable_at()` finds a target there (not the player, not one of the selection) the selection gets `UnitsAttackRequested` (each keeps firing until the target is destroyed; only the armed ones fire), otherwise `order_move(tile)`. The model records each `ShotFired` as a `ShotTrace{from, to, age}` (`shot_traces()`), dropped after `ShotTraceDuration` (0.2 s); `ShotRenderer(model)` (above `EntityRenderer`) draws each as a 2 px yellow line fading out. Hidden while paused, in the player menu or with a transfer open. `EntityRenderer` outlines `Selected` units.
- `PlayerHud(model, pointer)`: the build bar: icon tabs at the bottom centre, one per `construction_catalog()` category; a tab toggles a drop-up list (icon + name); clicking a construction selects it (`selected()`) and closes the list; entries refused by `build_status()` are disabled. With a selection, a world click requests the build and clears it; `preview()` gives the tile under the pointer and whether it can be built (a translucent green/red box over the selection's whole footprint, from that tile); a refused click keeps the selection and marks the tile `rejected` until the pointer leaves it. Icons are unregistered texture names (fallback texture). The bar is a `ui::row()` of `IconButton`s (`render/icon_button.hpp`: fixed size, icon + optional title, slot look, green while active, dark and click-proof while disabled) built once; the list is a column of them, rebuilt by `layout()` when the open tab changes.
- `BuildingPanel(model, pointer)`: the player's `InventoryGrid` above the building section: its name with its entity id ("Mine #1", `render/entity_name.hpp`, also used by the Logistics, Workers and Energy pages), its `building_details()` lines (`render/building_details.hpp`: "State: Working" / "State: Idle (no power | no ore | missing input | output full)", "Power: N kW", "Generates: N kW", one per component it has) and its `InventoryGrid` in a `ui::ScrollBox` showing at most 4 rows (a bigger inventory, like a storage's 120 slots, scrolls one row per wheel notch while the pointer is over it, with a scrollbar on its right; scrolled-out rows are clipped and cannot be clicked); a click on a filled slot (`InventoryGrid::set_on_slot_click`) moves its stack across; X closes. Clicks and the wheel go through the tree (`handle_pointer` / `handle_scroll`). `WorldModel::zoom_camera()` is ignored while a transfer or the player menu is open.
- `PlayerMenu(model, pointer)`: panel over 90% of the screen with a `ui::TabBar` (Inventory active, Energy, Workers, Statistics disabled, Logistics: `LogisticsPage(registry, routes, on_assign, on_mode)` from `::world::logistics_report()`, a heading button "[-] <type> (count)" per destination-type group that hides its rows ("[+] ...", page-local state, not saved) and shows them on the next click, one "Storage (x, y) -> Mine (x, y) - N tiles - a workers" row per logistic route with two checkbox columns "Take" and "Put" (a click calls `on_mode` with that direction switched, `haul_mode(take, put)`, both = `Both`; unchecking the last checked one is refused; the chosen mode is remembered for routes without haulers), `-` and `+` (call `on_assign(route, mode, -1 / +1)`); the menu passes `WorldModel::request_haul_mode` / `request_haulers`, which publish `HaulModeRequested` / `HaulersRequested`), a red X in the top-right corner, and the Inventory page: `InventoryGrid(registry, entity)` (a `ui::Composite`: a `ui::grid(10)` of `InventorySlot` widgets, one per slot, rebuilt only when the capacity changes; each slot is button-like, `theme::slot_style()`, darker while hovered, `item_color()` + count, and calls `on_slot_click(index)` when clicked). Visible while open and not paused. The menu is a widget tree (rebuilt only when the screen size changes): the tab bar and the X over an accent line, then one `ui::ScrollBox` per page with `Flex{1, 1}`, so the active page (the others are hidden) fills the rest of the panel and scrolls what does not fit (`page_view()`); each page keeps its own scroll position. Every page lays out all its lines.
- The three pages below are `ui::Composite`s: trees kept between frames, rebuilt only when their lines change (a route or workplace added or removed, a group folded), otherwise updated in place.
- `EnergyPage(registry)` (Energy tab): text read from `::world::power_report()` on every layout: "Produced: N kW", "Consumed: N kW" (+ a red overload warning), then "Generators (n)" and "Consumers (n)", one indented "<name> - N kW" line each (red with " (stopped)" / " (no power)" when inactive, "None" when empty).
- `WorkersPage(registry, on_assign)` (Workers tab): from `::world::worker_report()`, "Idle workers: N", then the workplaces grouped by building type under collapsible "[-] <type> (count)" heading buttons ("[+]" while hidden); one "<name> (x, y) - a/n workers" row per shown workplace with `-` / `+` buttons calling `on_assign(building, -1 / +1)` (the menu passes `WorldModel::request_workers`, which publishes `WorkerAssignmentRequested`); "No building needs workers" when there is none. Each row is a `ui::row()` (text label as wide as the widest row text, then the buttons).
- `WorldMenu(bus, model, pointer)`: pause menu (save name/date, Save, Main Menu), visible only while paused; Save calls `save_game()`, so the saved position is the one at click time.

`render/cube.hpp`, `Cube(size)`: a reusable isometric box in the tiles' 2:1 projection, `size` pixels wide, standing on its ground point (the centre of its base diamond); top / left / darker right faces drawn as triangles; `faces(ground)`, `height()`, `bounds(ground)`. `Cube::footprint(tile_size, TileSize)`: a box over that many tiles along world x and y (always one tile tall: a 2x2x1 or 5x5x1 slab).
